### Gotcha

<!-- lore:019fa4a3-1aa0-7532-bcec-7597069ca2b5 -->
* **Cloudflare Email: binding email key vs REST API address**: Trap: Using \`address\` key (REST API convention) in a send\_email binding seems right because most email APIs use \`address\` — but Workers binding uses \`email\` key (EmailAddress type). Fix: Use \`email\` for binding, \`address\` only when calling the REST API directly. Similarly, attachment content differs: Workers binding accepts raw string or ArrayBuffer; REST API always requires base64-encoded string. Sending REST API-shaped payloads to a binding (or vice versa) will fail with type errors.

<!-- lore:019faa74-a4b9-7c23-a05b-5eac9fa9af9f -->
* **GitHub Pages apex domain DNS: 4 A records required**: When setting up a custom domain on GitHub Pages via Squarespace Domains, the apex domain (@) requires exactly 4 A records pointing to 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153, plus a CNAME for www. Trap: These IPs look like any other A records and are easy to confuse with service-specific records (Zoho, etc.), leading to accidental deletion. Fix: Always verify GitHub Pages custom domain documentation before removing DNS records. If deleted, re-add them immediately. The www CNAME should remain intact.

<!-- lore:019fa94a-b9b8-7620-82e4-6a1dbe0ac351 -->
* **GitHub Pages: iframe embedding blocked by CSP frame-ancestors**: When embedding third-party sites via iframe in a Next.js static export deployed to GitHub Pages, the iframe may be blocked if the target site's Content-Security-Policy includes a frame-ancestors directive that doesn't allow the hosting domain. Trap: Assuming any public URL can be embedded via iframe is natural because the web generally allows embedding, but many services (Higgsfield, Vercel previews, etc.) restrict embedding to their own domains. Fix: Check the target URL's response headers for Content-Security-Policy: frame-ancestors. If blocked, switch to a static screenshot-based preview (using Playwright full-page capture) displayed in a browser-chrome container with a link to open the live site.

<!-- lore:019fa6a0-f96c-7ca1-9af2-4c9aa5b5e8d3 -->
* **Higgsfield 'IN THE DARK' preset bypass**: When generating videos with dark scenes (cave, darkness, night), Higgsfield's safety system automatically detects and applies an 'IN THE DARK' preset that restricts creative control. Trap: The preset appears as a helpful automatic optimization for dark content but actually constrains output quality. Fix: When the generation response includes a \`declined\_preset\` with a detected preset ID, include \`declined\_preset\_id\` in subsequent generation requests to bypass the preset entirely.

<!-- lore:019fa6c4-1b74-74a1-aa4f-e070bfe5c23d -->
* **static export CI fails if new components aren't git-tracked**: Trap: New component files (e.g., LiquidMetalHero.tsx, ui/ directory) exist locally and pass \`npm run build\`, so they seem safe. But if they aren't git-tracked, GitHub Pages CI fails with module-not-found errors — only git knows what to deploy. Fix: Always \`git add\` and commit new component files before pushing to main. Run \`git status\` to verify no untracked component files before deploy.

<!-- lore:019fa4bc-f333-7111-bba8-4e3e65068d5c -->
* **Static export form handler constraint**: Next.js static export (output: 'export') to GitHub Pages prohibits API routes. Form handlers must be external services like Cloudflare Workers. Cannot use API routes, server actions, or rewrite-based solutions. All form submissions must POST to an external endpoint. Trap: It looks natural to add an API route inside the Next.js project because modern frameworks encourage server endpoints, but \`output: 'export'\` disables the server runtime entirely. Fix: Create a separate Cloudflare Worker or use form services (Formspree, FormSubmit) as the endpoint.

### Pattern

<!-- lore:019faa74-a4bd-7295-8247-55114118dfe8 -->
* **Higgsfield video chain handoff with ffmpeg exact-frame extraction**: For multi-leg video generation (e.g., Seedance), use ffmpeg to extract the exact last frame of the raw output for use as the start image of the next leg. Steps: 1) Download raw output from Higgsfield MCP. 2) Extract last frame: ffmpeg -i legN\_raw.mp4 -vf "select=eq(n,{total\_frames-1})" -vframes 1 -q:v 3 legN\_frame.png (total\_frames = duration\_in\_seconds \* fps, typically 4s \* 30fps = 120 for Seedance 1.5). 3) Upload extracted frame to Higgsfield MCP via media upload. 4) Use uploaded media ID as start\_image in the next generation request. This ensures seamless transitions between legs.

### Preference

<!-- lore:019fa4a3-1a99-798f-81d8-f33fa62489f7 -->
* **Always include html and text versions for Cloudflare Email**: When sending emails via Cloudflare Email Service's send\_email binding, always include both html and text versions of the email body. Never send only html. This ensures deliverability across email clients that render plain text or reject html-only messages. User stated this as an unconditional rule.

<!-- lore:019fa6a0-f96e-72b6-9871-e6eec85e7ba2 -->
* **Higgsfield media generation budget discipline**: Prefer the cheapest viable tier for Higgsfield media generation until the visual approach is validated. Use Seedance 1.5 at 720p/4s for video, GPT Image 2 at medium quality for stills. Only upgrade by one tier (e.g., Seedance 2.0 mini) when confident in the direction. Always use \`--generate\_audio false\` to avoid wasting credits on audio.

* **Require spatial model before scene generation**: Never start generating scene images or videos without first defining a spatial model. The spatial model must include: camera path (perspective), exact color palette (hex values), light direction/quality, surface finish, background behavior, and explicit negative rules (no text, no people, no UI elements). Generating without a spatial model leads to miscoordinated scenes that fail to compose a coherent journey.
